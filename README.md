# kerio-mcp

MCP-сервер для почтового ящика на **Kerio Connect**. Работает через HTTPS JSON-RPC API веб-клиента
(`https://<хост>/webmail/api/jsonrpc/`), то есть нужен только порт 443. Поэтому он работает и на
обычном компьютере, и в облачных сессиях, где IMAP (порт 993) и SMTP (465/587) закрыты.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `list-folders` | список папок |
| `list-emails` | последние письма папки (`inbox`, `sent`, `drafts`, `trash`, `junk` или имя папки); `unreadOnly` — только непрочитанные |
| `search-emails` | поиск по теме и отправителю |
| `read-email` | читает письмо: заголовки, текст (HTML очищается, скрытый текст удаляется), пронумерованный список вложений |
| `download-attachment` | скачивает вложения письма в папку файлов (все или одно — по номеру или имени) |
| `list-files` | показывает, что лежит в папке файлов |
| `send-email` | отправляет письмо (текст); можно прикрепить файлы из папки файлов |
| `draft-email` | сохраняет письмо в «Черновики», тоже с вложениями |
| `mark-as-read` | отметить прочитанным / непрочитанным |
| `flag-email` | поставить или снять флажок (по умолчанию красный) |
| `move-emails` | перенести письма в другую папку (у перенесённых писем новые id) |
| `delete-email` | в «Удалённые»; `permanent: true` — удалить совсем |
| `create-folder` | создать папку |
| `list-events` | события календаря за период (повторяющиеся уже раскрыты), по умолчанию ближайшие 7 дней |
| `read-event` | событие целиком: время, место, описание, участники и их ответы |
| `create-event` | создать событие; с `attendees` это собрание, и Kerio рассылает приглашения |
| `update-event` | изменить событие или собрание (только указанные поля; для повторяющихся — одно, это и следующие или все) |
| `delete-event` | удалить событие или одно повторение |
| `list-invitations` | приглашения, изменения и отмены собраний, ожидающие в календаре |
| `respond-to-invitation` | принять, принять условно или отклонить приглашение |
| `check-availability` | когда заняты указанные люди |
| `find-meeting-time` | общее свободное время участников в рабочие часы |

Не поддерживается: контакты, задачи, заметки, удаление папок (API не принимает известные параметры).

## Календарь и собрания

Собрание — это событие с участниками. Примеры запросов:

- «что у меня в календаре на этой неделе»
- «найди время на час, когда свободны Иванов и Петров, на следующей неделе» (`find-meeting-time`)
- «назначь собрание «Планирование» на завтра в 15:00 на час, пригласи ivanov@example.com и petrov@example.com»
- «перенеси собрание на 16:30», «отмени встречу в пятницу»
- «какие у меня приглашения?», «прими приглашение на планёрку»

Важно:

- **Приглашения и отмены уходят людям от вашего имени.** Просите Claude показывать участников и время и
  спрашивать подтверждение перед созданием, изменением и удалением собрания.
- **Время** указывается по часовому поясу ящика (как в календаре), например `2026-10-30T15:00`. Часовой пояс сервер
  берёт из ящика; при необходимости задайте его переменной `KERIO_TIMEZONE_OFFSET` (например `+03:00`).
- **Занятость** видна только у людей с календарём на этом сервере; для остальных (внешних адресов) Claude скажет, что
  данных нет, и их время не проверяется.
- **Не проверено на реальном сервере**: рассылка приглашений участникам, ответ на приглашение
  (`respond-to-invitation`) и отмена собрания с участниками. Они написаны по описанию API Kerio. Проверьте один раз,
  пригласив самого себя на тестовое собрание. События без участников (создание, чтение, перенос, повторы, события на
  весь день, удаление, свободное время) проверены на живом ящике.

## Файлы: загрузка и скачивание

Все файлы, которые сервер читает или пишет, лежат в **одной папке** (по умолчанию `~/kerio-mcp-files`,
меняется переменной `KERIO_FILES_DIR`):

- **Скачать вложение.** «Скачай вложения из письма …» — файлы окажутся в `downloads/<код письма>/`. Существующие
  файлы не перезаписываются (к имени добавляется `(1)`).
- **Отправить файл.** Положите файл в папку файлов (например, `~/kerio-mcp-files/КП.pdf`) и скажите:
  «отправь письмо на … и приложи КП.pdf». Подпапки работают: `документы/счёт.xlsx`.
- **Что там лежит** — «покажи файлы» (`list-files`).

Пути вне этой папки сервер отклоняет, в том числе через `..` и ссылки. Это защита: письмо со скрытой
инструкцией не сможет заставить ИИ отправить, например, ваши ключи или пароли. Лимит размера файла —
25 МБ (`KERIO_MAX_FILE_MB`).

## Установщик для Windows (самый простой способ)

Для тех, кто не хочет возиться с настройками: готовый пакет `kerio-mcp-installer.zip` лежит на странице
[Releases](../../releases/latest) этого репозитория (раздел Assets). Внутри `install.bat`.

1. Скачать `kerio-mcp-installer.zip`, распаковать, дважды щёлкнуть `install.bat`.
2. Ответить на вопросы: почта, пароль (не отображается), папка установки, папка для файлов.
3. Установщик проверит вход в почту, скопирует программу и личную копию `node.exe`, сохранит пароль в
   `config.json` (доступ только у вашей учётной записи Windows) и сам пропишет сервер в **Claude Desktop**
   (и в версию из Microsoft Store) и в **Claude Code** (команда `claude mcp add --scope user`, если Claude Code
   установлен).
4. Перезапустить Claude Desktop. Удалить можно через `uninstall.bat` в папке установки (папка с файлами остаётся).

Node.js ставить не нужно: если подходящего нет, установщик скачает `node.exe` с nodejs.org и проверит
контрольную сумму SHA-256. Пакет собирается командой (на Linux или macOS, нужны Node.js и `zip`):

```bash
installer/build.sh mail.example.com     # адрес сервера попадёт только в пакет, не в репозиторий
```

Результат: `dist/kerio-mcp-installer.zip`. Без адреса в команде установщик спросит его у пользователя.

### Как выпустить новую версию

На GitHub: Releases → Draft a new release → новый тег вида `v1.0.1` → Publish. Либо из терминала:
`git tag v1.0.1 && git push origin v1.0.1`. Workflow `Release installer` сам прогонит тесты, соберёт архив и прикрепит
его к релизу. Чтобы пакет сразу знал адрес вашего сервера, задайте переменную репозитория `KERIO_DEFAULT_HOST`
(Settings → Secrets and variables → Actions → Variables). **Только для приватного репозитория**: в публичном
релиз виден всем, и адрес тоже.
Для установки без вопросов (администратору): `install.bat --yes --email ivan@example.com --install-dir D --files-dir F`
и пароль в переменной `KERIO_SETUP_PASSWORD`.

## Использование в обычной сессии (на вашем компьютере)

Три переменные окружения, которые нужны серверу:

| Переменная | Значение |
|---|---|
| `KERIO_HOST` | хост веб-клиента, например `mail.example.com` (без `https://`) |
| `KERIO_USER` | полный адрес ящика, например `you@example.com` |
| `KERIO_PASSWORD` | пароль |
| `KERIO_FILES_DIR` | (необязательно) папка для файлов, по умолчанию `~/kerio-mcp-files` |
| `KERIO_MAX_FILE_MB` | (необязательно) максимальный размер файла, МБ; по умолчанию 25 |
| `KERIO_TIMEZONE_OFFSET` | (необязательно) часовой пояс календаря, например `+03:00`; по умолчанию берётся из ящика |

### Вариант 1. Claude Desktop

1. Откройте файл настроек (если его нет, создайте):
   - macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`
   - Windows: `%APPDATA%\Claude\claude_desktop_config.json`
   (или в приложении: Settings → Developer → Edit Config).
2. Добавьте сервер (пути на Windows пишите с двойными обратными слэшами, `C:\\Users\\...\\kerio-mcp\\server.js`):

   ```json
   {
     "mcpServers": {
       "kerio-mail": {
         "command": "node",
         "args": ["/полный/путь/к/kerio-mcp/server.js"],
         "env": {
           "KERIO_HOST": "mail.example.com",
           "KERIO_USER": "you@example.com",
           "KERIO_PASSWORD": "ваш-пароль"
         }
       }
     }
   }
   ```
3. **Полностью закройте и снова откройте Claude Desktop** (не просто окно).
4. В новом чате должен появиться значок инструментов с `kerio-mail`. Проверьте: «покажи последние 5 писем во входящих».

### Вариант 2. Claude Code в терминале на вашем компьютере

Одной командой (сервер будет доступен во всех ваших проектах):

```bash
claude mcp add kerio-mail --scope user \
  --env KERIO_HOST=mail.example.com \
  --env KERIO_USER=you@example.com \
  --env KERIO_PASSWORD='ваш-пароль' \
  -- node /полный/путь/к/kerio-mcp/server.js
```

Проверка: `claude mcp list` (сервер `kerio-mail` должен быть в состоянии Connected), затем в сессии `claude`
спросите: «покажи непрочитанные письма».

Либо без пароля в командной строке: положите `KERIO_HOST`, `KERIO_USER`, `KERIO_PASSWORD` в файл `.env`
в папке `kerio-mcp` (образец `.env.example`), и сервер сам их прочитает:

```bash
cp .env.example .env     # заполните значения
claude mcp add kerio-mail --scope user -- node /полный/путь/к/kerio-mcp/server.js
```

### Вариант 3. Из папки репозитория

Если запускаете `claude` прямо в папке `kerio-mcp`, файл `.mcp.json` уже регистрирует сервер `kerio-mail`.
Он берёт значения из переменных окружения, поэтому задайте их перед запуском:

```bash
export KERIO_HOST=mail.example.com KERIO_USER=you@example.com KERIO_PASSWORD='ваш-пароль'
claude
```

### Как пользоваться

Просто пишите задачи обычным языком, например:

- «покажи непрочитанные письма за сегодня»
- «найди письма от Иванова про счёт и коротко перескажи»
- «скачай вложения из последнего письма от Иванова»
- «отправь письмо на … с темой … и приложи файл КП.pdf» (файл должен лежать в папке файлов)
- «ответь на письмо с id … текстом …» (перед отправкой Claude покажет текст, подтвердите его)
- «пометь прочитанными и красным флажком письма …»

Всё остальное (куда класть письма, что считать важным) решаете вы в запросе. Отправка идёт от имени
вашего ящика, поэтому просите показывать письмо перед отправкой.

### Проверка и поиск проблем

```bash
npm run inspect     # MCP Inspector: список инструментов и пробные вызовы
```

| Симптом | Причина |
|---|---|
| `Kerio login failed` | неверный логин или пароль (или нужен пароль приложения) |
| `Kerio is not reachable` | хост указан неверно или недоступен порт 443; проверьте WebMail в браузере |
| ошибка сертификата | имя в `KERIO_HOST` не совпадает с именем в сертификате сервера |
| Claude не видит инструменты | после правки конфигурации Desktop не перезапущен полностью |

## Использование в облачной сессии

Репозиторий можно подключить к облачной сессии Claude Code. Задайте `KERIO_HOST`, `KERIO_USER`,
`KERIO_PASSWORD` в секретах окружения сессии и откройте репозиторий в ней: файл `.mcp.json`
зарегистрирует сервер. Так как нужен только HTTPS, облачные ограничения на IMAP/SMTP здесь не мешают.

## Безопасность

- **Пароль не хранится в репозитории**: `.env` в `.gitignore`. Не вставляйте пароль в чат.
- Содержимое писем в ответах помечено как данные, а не инструкции. Скрытые элементы HTML
  (`display:none`, `font-size:0` и т. п.) и невидимые символы удаляются.
- Отправка идёт от вашего имени: просите показывать текст письма перед отправкой.

## Как это устроено

- `src/kerio-client.js` — клиент API: вход при первом запросе, повторный вход при «Session expired»,
  повторы при сетевых обрывах, перевод HTML писем в текст без скрытого текста.
- `src/files.js` — папка файлов: проверка путей, безопасные имена, лимит размера.
- `src/calendar.js`, `src/calendar-tools.js`, `src/dates.js` — календарь, собрания, свободное время, даты Kerio.
- `src/tools.js` — описание инструментов MCP.
- `server.js` — запуск stdio-сервера.

## Особенности API Kerio, найденные при разработке

- Фильтры по `isSeen`/`isFlagged` сервер принимает, но игнорирует: непрочитанные отбираются на стороне
  клиента (просматривается до 1000 последних писем).
- Перенос письма: `Mails.set` с полем `folderId`. Удаление насовсем: `Mails.remove` с `ids`.
- Отправка: создать черновик (`Mails.create`), затем `Mails.set` с `send: true` и полем `from`.
- Даты календаря имеют вид `20261030T150000+0300` (местное время ящика) или `20261031` для событий на весь день;
  сервер **игнорирует смещение во входящих датах** и считает время местным, поэтому даты нужно отправлять в часовом
  поясе ящика. У события на весь день конец — следующий день.
- События: `Events.create/set/getById/remove`; список за период — `Occurrences.get` с условиями на `start` и `end`;
  одно повторение меняется и удаляется через `Occurrences.set/remove` с `modification` (`modifyThis` и др.);
  ответ на приглашение — `Occurrences.setPartStatus`; приглашения — `Events.getEventUpdateList`; занятость — `FreeBusy.get`.
- Загрузка файла: `POST /webmail/api/jsonrpc/upload/` (multipart, поле `file`, заголовки `X-Token` и cookie),
  ответ `result.fileUpload.id`. Этот id (живёт около часа) передаётся в `attachments[].id` при `Mails.create`.
- Скачивание вложения: адрес из поля `url` вложения письма (содержит `sid`), запрос с теми же cookie и `X-Token`.
